विशेष टॉपिक: .NET फ्रेमवर्क आर्किटेक्चर, CLR और गार्बेज कलेक्शन

बीसीए पंचम (V) सेमेस्टर • विषय: सीएएससी-14T (.NET Programming) • शत-प्रतिशत परीक्षा-उपयोगी विस्तृत नोट्स

1. परिचय एवं परिभाषा (Introduction & Definition)

.NET Framework (.डॉट नेट फ्रेमवर्क) माइक्रोसॉफ्ट द्वारा विकसित एक सॉफ्टवेयर विकास मंच है जो विंडोज और अन्य प्लेटफार्मों पर एप्लीकेशन बनाने और चलाने के लिए व्यापक वातावरण प्रदान करता है।

इस फ्रेमवर्क का सबसे महत्वपूर्ण हिस्सा CLR (Common Language Runtime - कॉमन लैंग्वेज रनटाइम) है, जो प्रबंधित कोड (Managed Code) के निष्पादन को नियंत्रित करता है। इसके साथ ही, Garbage Collector (गार्बेज कलेक्टर) रैम (RAM) में पड़ी उन पुरानी और बेकार हो चुकी वस्तुओं (Unused objects) को स्वचालित रूप से साफ करता है जिनकी एप्लीकेशन को अब कोई आवश्यकता नहीं होती।

2. मुख्य बिंदु एवं घटक (Key Points & Components)

  • IL (Intermediate Language): जब हम C# या VB.NET में कोड लिखते हैं, तो कम्पाइलर उसे सीधे मशीन कोड में न बदलकर IL कोड में बदलता है।
  • JIT (Just-In-Time) Compiler: यह रन-टाइम के दौरान IL कोड को मशीन-विशिष्ट बाइनरी कोड (Machine code) में परिवर्तित करता है।
  • Garbage Collection (GC): यह मेमोरी लीक (Memory leak) की समस्या को दूर करता है क्योंकि डेवलपर को मैन्युअल रूप से मेमोरी खाली नहीं करनी पड़ती।

3. वास्तुकला एवं प्रवाह आरेख (Architecture & Flowchart Diagram)

.NET फ्रेमवर्क और CLR की संकलन एवं निष्पादन प्रक्रिया का प्रवाह आरेख नीचे दर्शाया गया है:

+---------------------------------------------------------+
|        Source Code (C# / VB.NET / F# Language)          |
+---------------------------------------------------------+
                             ↓ (Language Compiler)
+---------------------------------------------------------+
|            MSIL / IL Code + Metadata                    |
+---------------------------------------------------------+
                             ↓ (CLR / JIT Compiler)
+---------------------------------------------------------+
|                Native Machine Code                      |
+---------------------------------------------------------+
                             ↓
+---------------------------------------------------------+
|         Execution by CPU & Garbage Collection           |
+---------------------------------------------------------+

आरेख विवरण (Diagram Description): सोर्स कोड पहले IL कोड में कम्पाइल होता है, फिर CLR के भीतर JIT कम्पाइलर उसे मशीन कोड में बदलकर निष्पादित करता है।

4. अनुप्रयोग (Applications)

इस वास्तुकला का उपयोग निम्नलिखित क्षेत्रों में होता है:

  • क्रॉस-लैंग्वेज इंटीग्रेशन (Cross-language integration) यानी एक ही प्रोजेक्ट में C# और VB.NET का एक साथ उपयोग।
  • सुरक्षित और स्वचालित मेमोरी प्रबंधन वाले उच्च-प्रदर्शन सॉफ्टवेयर के निर्माण में।

5. लाभ, हानियां एवं सीमाएं (Pros, Cons & Limits)

### लाभ (Pros / Advantages):
  • स्वचालित गार्बेज कलेक्शन के कारण डेवलपर्स को मेमोरी प्रबंधन की चिंता नहीं करनी पड़ती।
  • प्रभावी सुरक्षा (Code Access Security) और मजबूत रन-टाइम जाँच मिलती है।
### हानियां एवं सीमाएं (Cons & Limits):
  • JIT कम्पाइलर और गार्बेज कलेक्टर के बैकग्राउंड में चलने के कारण शुरुआती निष्पादन में हल्का सा अतिरिक्त समय लग सकता है।

6. तुलना तालिका: Managed Code बनाम Unmanaged Code (Comparison)

तुलनात्मक बिंदु Managed Code (प्र प्रबंधित कोड) Unmanaged Code (अप्रबंधित कोड)
नियंत्रण यह सीधे **CLR** के नियंत्रण और सुरक्षा के अधीन चलता है। यह सीधे ऑपरेटिंग सिस्टम के अधीन चलता है (जैसे C/C++)।
मेमोरी प्रबंधन यह **Garbage Collector** द्वारा स्वचालित रूप से प्रबंधित होता है। इसमें मेमोरी मैन्युअल रूप से (malloc/free) साफ करनी पड़ती है।

7. प्रोग्रामिंग कोड उदाहरण (Code Snippet)

C# में गार्बेज कलेक्टर को स्पष्ट रूप से कॉल करने का संक्षिप्त उदाहरण:

using System; class Program { static void Main() { Console.WriteLine("एप्लीकेशन चल रही है..."); // भारी वस्तु का निर्माण byte[] largeArray = new byte[1000000]; // काम पूरा होने के बाद गार्बेज कलेक्शन को सक्रिय करना GC.Collect(); GC.WaitForPendingFinalizers(); Console.WriteLine("गार्बेज कलेक्टर द्वारा अप्रयुक्त मेमोरी साफ कर दी गई है।"); } }

UNIT 3 • TOPIC 1

Classes, Objects, Constructors (Sub New), Destructors एवं Encapsulation

1. Technical Definitions & Concepts

Technical Definition of Class & Object: A Class is a user-defined blueprint defining fields, properties, and methods. An Object is an active concrete instance of a class allocated on the Managed Heap.

Technical Definition of Constructor & Destructor: A Constructor in VB.NET is a special procedure named Sub New() executed automatically when an object is created with the New keyword to initialize state. A Destructor (Protected Overrides Sub Finalize()) releases unmanaged resources before Garbage Collection.

सरल हिंदी में समझें: Class एक नक्शा (Blueprint) है, जैसे मकान का नक्शा। Object उस नक्शे से बना असली मकान है जो रैम (Managed Heap) में जगह लेता है। जब भी New कीवर्ड से कोई ऑब्जेक्ट बनता है, तो उसका Constructor (Sub New()) सबसे पहले अपने आप चलता है ताकि वेरिएबल्स में शुरुआती मान (Initial Values) डाले जा सकें। Encapsulation डेटा और फंक्शन्स को एक सिंगल क्लास कैप्सूल में बांधकर अनधिकृत छेड़छाड़ से सुरक्षित रखता है।

UNIT 3 • TOPIC 2

Inheritance, Method Overriding (Overridable/Overrides), Shadows एवं MyBase

1. Technical Definitions & Concepts

Technical Definition of Inheritance: Inheritance is an OOP mechanism allowing a derived child class to acquire members of an existing base class using the Inherits statement.

Technical Definition of Overriding: Replacing a base class method marked with Overridable with a specialized child class implementation using the Overrides keyword.

सरल हिंदी में समझें: Inheritance का मतलब है पुरानी क्लास के कोड को नई क्लास में सीधे ले लेना ताकि कोड दोबारा न लिखना पड़े। बेस क्लास का मेथड अगर Overridable है, तो चाइल्ड क्लास Overrides लिखकर उसे अपने हिसाब से बदल सकती है। यदि चाइल्ड क्लास को अपने पैरेंट का पुराना मेथड कॉल करना हो, तो वह MyBase.MethodName() का उपयोग करती है।

UNIT 3 • TOPIC 3

Polymorphism: Compile-Time (Overloads) बनाम Run-Time (Overrides) Binding

1. Technical Definitions & Concepts

Polymorphism: पॉलीमॉर्फिज्म ग्रीक शब्द है जिसका अर्थ है "अनेक रूप" (One Name, Many Forms)। यह एक ही इंटरफेस या मेथड नाम को अलग-अलग डेटा टाइप्स के लिए अलग-अलग तरह से काम करने की अनुमति देता है।

Compile-Time Polymorphism (Method Overloading): एक ही क्लास में समान नाम के कई मेथड्स बनाना, जिनमें पैरामीटर्स की संख्या या डेटा टाइप अलग-अलग होते हैं (Overloads कीवर्ड)।

Run-Time Polymorphism (Method Overriding): इनहेरिटेंस में बेस क्लास के मेथड को चाइल्ड क्लास में ओवरराइड करना, जिसका निर्णय रन-टाइम पर ऑब्जेक्ट के वास्तविक प्रकार द्वारा लिया जाता है।

2. Comparison: Compile-Time बनाम Run-Time Polymorphism

तुलना बिंदुCompile-Time (Method Overloading)Run-Time (Method Overriding)
कीवर्डOverloadsOverridable (Base) और Overrides (Child)
क्लास की सीमाएक ही क्लास के अंदर होता हैबेस और चाइल्ड क्लास के बीच होता है
सिग्नेचरपैरामीटर्स का प्रकार या संख्या भिन्न होना अनिवार्य हैसिग्नेचर बिल्कुल समान होना अनिवार्य है
बाइंडिंग का समयकंपाइल-टाइम (Early Binding - तीव्र गति)रन-टाइम (Late Binding - वर्चुअल टेबल द्वारा)

UNIT 3 • TOPIC 4

Abstract Classes (MustInherit), MustOverride एवं NotInheritable Classes

1. Technical Definitions & Concepts

MustInherit (Abstract Class): वह क्लास जिसका New कीवर्ड द्वारा सीधे ऑब्जेक्ट नहीं बनाया जा सकता। इसका उपयोग केवल बेस क्लास के रूप में इनहेरिट करने के लिए किया जाता है।

MustOverride (Abstract Method): वह मेथड जिसका बेस क्लास में कोई कोड (Body) नहीं होता; इसे इनहेरिट करने वाली प्रत्येक चाइल्ड क्लास को ओवरराइड करना अनिवार्य होता है।

NotInheritable (Sealed Class): वह क्लास जिसे आगे इनहेरिट करने से रोक दिया गया हो ताकि कोई इसका चाइल्ड क्लास न बना सके।

2. Comparison: Abstract Class (MustInherit) बनाम Concrete Class

तुलना बिंदुAbstract Class (MustInherit)Concrete Class (सामान्य क्लास)
ऑब्जेक्ट निर्माण (Instantiation)सीधे ऑब्जेक्ट नहीं बन सकता (Dim x As New Base() एरर देगा)सीधे New कीवर्ड से ऑब्जेक्ट बनाया जा सकता है
MustOverride मेथड्सशामिल हो सकते हैं (बिना कोड वाले मेथड्स)केवल पूर्ण रूप से कोडित मेथड्स होते हैं
उद्देश्यभविष्य की क्लासेस के लिए सामान्य रूपरेखा (Contract) तय करनावास्तविक बिजनेस लॉजिक लागू करना

Interfaces (Interface...Implements) एवं Multiple Inheritance समाधान

1. Technical Definitions & Concepts

Interface: एक शुद्ध अनुबंध (Pure Contract) जिसमें केवल मेथड्स, प्रॉपर्टीज और इवेंट्स के नाम घोषित होते हैं, लेकिन कोई कार्यान्वयन (Implementation) नहीं होता।

Multiple Inheritance Solution: VB.NET में एक क्लास एक से अधिक बेस क्लासेस को इनहेरिट नहीं कर सकती (Multiple Class Inheritance प्रतिबंधित है)। परंतु एक क्लास एक से अधिक Interfaces को एक साथ लागू (Implements) कर सकती है, जिससे Multiple Inheritance की आवश्यकता सुरक्षित रूप से पूरी होती है।

Properties: ReadOnly, WriteOnly एवं Get / Set Blocks

1. Technical Definitions & Concepts

Property: एक ऐसा क्लास सदस्य जो बाहर से देखने पर पब्लिक वेरिएबल जैसा दिखता है, लेकिन आंतरिक रूप से Get और Set एक्सेसर्स द्वारा डेटा की वैधता (Validation) की जांच करता है।

ReadOnly Property: जिसमें केवल Get ब्लॉक होता है; इसका मान केवल पढ़ा जा सकता है, बदला नहीं जा सकता।

WriteOnly Property: जिसमें केवल Set ब्लॉक होता है (उदा. पासवर्ड स्टोर करने हेतु)।

UNIT 3 • TOPIC 7 (10-MARK EXAM FAVORITE)

Structured Exception Handling (SEH): Try...Catch...Finally एवं Throw

1. Technical Definitions & Concepts

Exception: रन-टाइम पर आने वाली अप्रत्याशित त्रुटि (जैसे DivideByZeroException, FileNotFoundException) जो प्रोग्राम को असामान्य रूप से क्रैश कर सकती है।

Try...Catch...Finally Blocks:
• Try Block: वह संदिग्ध कोड जिसे रन करके मॉनिटर करना है।
• Catch Block: एरर आने पर उसे पकड़कर सुरक्षित समाधान देना।
• Finally Block: वह कोड जो हमेशा निष्पादित होता है (चाहे एरर आए या न आए), ताकि फ़ाइलें और डेटाबेस कनेक्शन बंद किए जा सकें।
• Throw Statement: किसी त्रुटि को स्पष्ट रूप से ट्रिगर करना (Throw New Exception("अमान्य मान"))।

UNIT 3 • TOPIC 8

Unstructured Exception Handling (On Error GoTo) बनाम Structured Exception Handling

1. Technical Definitions & Concepts

Unstructured Exception Handling: पुरानी VB6 शैली की एरर हैंडलिंग जो On Error GoTo [LineLabel] या On Error Resume Next और Err ऑब्जेक्ट पर आधारित होती है।

Structured Exception Handling (SEH): आधुनिक .NET आर्किटेक्चर जो कोड को तार्किक ब्लॉक्स (Try...Catch...Finally) में विभाजित करता है और ऑब्जेक्ट-ओरिएंटेड एरर पदानुक्रम प्रदान करता है।

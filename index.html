UNIT 1 • TOPIC 1

Overview of .NET Framework, Features & Layered Architecture

1. Technical Definitions & Concepts

Technical Definition: The .NET Framework is a comprehensive, multi-language software development platform designed by Microsoft that provides a managed execution environment (CLR) and a massive Base Class Library (BCL) to build scalable desktop, web, and enterprise applications.

सरल हिंदी में व्याख्या: .NET Framework एक ऐसा आधुनिक और सुरक्षित सॉफ्टवेयर डेवलपमेंट प्लेटफॉर्म है जो ऑपरेटिंग सिस्टम और प्रोग्रामिंग भाषा (जैसे VB.NET, C#) के बीच एक मजबूत परत (Layer) की तरह कार्य करता है। यह प्रोग्रामर को मेमोरी लीक, क्रैश और सुरक्षा समस्याओं से मुक्ति दिलाकर तेज़ विकास का वातावरण प्रदान करता है।

2. Architecture Flowchart (5-Layered Architecture)

3. Core Components

  • CLR: .NET का वर्चुअल मशीन इंजन जो कोड को रन, सुपरवाइज और सिक्योर करता है।
  • BCL / FCL: हज़ारों रेडीमेड क्लासेज का संग्रह (File I/O, Networking, Graphics, Database Access)।
  • CTS & CLS: डेटा प्रकारों और बहुभाषी नियमों को मानकीकृत (Standardize) करने वाले नियम।

+ Rapid Application Development: BCL के पूर्व-निर्मित टूल्स से कोडिंग का 70% समय बचता है।- Platform Constraint: क्लासिक .NET फ्रेमवर्क मुख्य रूप से Windows पर निर्भर है।

  • Banking Core Terminals: बैंक काउंटरों पर चलने वाले सिक्योर ट्रांजैक्शन मैनेजमेंट पोर्टल्स।

UNIT 1 • TOPIC 2

Managed Execution Process, MSIL & JIT Compilation Types

1. Technical Definitions & Concepts

Technical Definition: The Managed Execution Process compiles source code into CPU-independent Microsoft Intermediate Language (MSIL). During execution, the Just-In-Time (JIT) compiler translates MSIL on demand into native CPU machine instructions.

सरल हिंदी में व्याख्या: .NET में कंपाइलर सीधे मशीन कोड (0 और 1) नहीं बनाता। वह पहले एक पोर्टेबल मध्यवर्ती कोड (MSIL) बनाता है। जब प्रोग्राम वास्तव में रन होता है, तब JIT कंपाइलर इसे आपके कंप्यूटर के प्रोसेसर के अनुसार फाइनल मशीन कोड में बदलता है।

2. Architecture Flowchart (Source Code to Machine Code)

3. Components (The 3 Types of JIT Compilers)

  • 1. Pre-JIT: पूरे प्रोग्राम को इंस्टॉलेशन के समय ही एक बार में नेटिव मशीन कोड में कंपाइल कर देता है (Ngen.exe टूल द्वारा)।
  • 2. Normal-JIT: केवल उन्हीं मेथड्स को कंपाइल करता है जिन्हें पहली बार कॉल किया जाता है, और उन्हें मेमोरी में कैश कर लेता है (.NET डिफ़ॉल्ट)।
  • 3. Econo-JIT: केवल तुरंत निष्पादन के लिए कंपाइल करता है लेकिन रैम में कैश नहीं करता (कम मेमोरी वाले डिवाइसेज के लिए)।

+ Portability: एक ही MSIL बाइटकोड 32-बिट और 64-बिट दोनों आर्किटेक्चर पर चल सकता है।- Decompilation Risk: ILDASM टूल से MSIL को आसानी से रिवर्स-इंजीनियर किया जा सकता है।

CLR Internal Architecture & Generational Garbage Collection

1. Technical Definitions & Concepts

Technical Definition: The Common Language Runtime (CLR) manages code execution through subsystems like the Class Loader, Type Checker, JIT Compiler, and Garbage Collector. The Garbage Collector (GC) automatically tracks, marks, and frees unreferenced objects on the Managed Heap using an episodic Generational Model (Gen 0, 1, and 2).

सरल हिंदी में व्याख्या: सी/सी++ में प्रोग्रामर को खुद मेमोरी खाली करनी पड़ती थी (जिससे मेमोरी लीक होती थी)। CLR में Garbage Collector (GC) बैकग्राउंड में जाकर उन ऑब्जेक्ट्स को पहचानता है जिनका प्रोग्राम में अब कोई इस्तेमाल नहीं हो रहा है, और उनकी रैम स्वतः खाली कर देता है।

4. Advantages & Disadvantages of Automatic GC

Advantages (लाभ)Disadvantages (हानियाँ)
+ No Dangling Pointers: डेवलपर द्वारा समय से पहले मेमोरी डिलीट करने का खतरा समाप्त।- Non-Deterministic: GC कब चलेगा यह CLR तय करता है, डेवलपर सीधे नियंत्रित नहीं कर सकता।
+ Automatic Heap Compaction: मेमोरी फ्रैग्मेंटेशन को अपने आप ठीक करता है।- Unmanaged Resources: डेटाबेस कनेक्शन या फ़ाइल हैंडल्स को GC स्वतः बंद नहीं कर पाता।

UNIT 1 • TOPIC 4

CTS (Common Type System), CLS, Value/Reference Types, Boxing & Unboxing

1. Technical Definitions & Concepts

CTS (Common Type System): .NET का आधिकारिक मानक जो यह तय करता है कि सभी समर्थित भाषाएँ डेटा प्रकारों को कैसे परिभाषित और उपयोग करेंगी ताकि पूर्ण टाइप-सेफ्टी बनी रहे।

CLS (Common Language Specification): बुनियादी नियमों और दिशा-निर्देशों का एक उप-समूह (Subset) जिसका पालन करने पर विभिन्न .NET भाषाओं (जैसे VB.NET और C#) के बीच निर्बाध बातचीत (Language Interoperability) संभव होती है।

Boxing & Unboxing: Value Type (Stack) को Reference Type (Heap Object) में बदलना Boxing कहलाता है। Object से वापस Value Type निकालना Unboxing कहलाता है।

UNIT 1 • TOPIC 5

Assemblies, Metadata, Manifest एवं GAC (Global Assembly Cache)

1. Technical Definitions & Concepts

Assembly: .NET एप्लिकेशन का प्राथमिक बिल्डिंग, परिनियोजन (Deployment) और सुरक्षा ब्लॉक है (.dll या .exe)। यह एक पूर्णतः Self-Describing घटक है।

Manifest & Metadata: Manifest असेंबली का पहचान पत्र है (नाम, वर्ज़न, निर्भरताएँ)। Metadata कोड के अंदर मौजूद हर क्लास, मेथड और डेटा टाइप का संपूर्ण बाइनरी विवरण रखता है।

Global Assembly Cache (GAC): कंप्यूटर के ऑपरेटिंग सिस्टम में स्थित एक केंद्रीय डायरेक्टरी (C:\Windows\Assembly) जहां शेयर्ड असेंबलीज़ को Strong Name के साथ रखा जाता है ताकि कई एप्लिकेशन्स उन्हें एक साथ साझा कर सकें।

UNIT 1 • TOPIC 6

Base Class Library (BCL/FCL), Namespaces एवं Event-Driven Programming

1. Technical Definitions & Concepts

Base Class Library (BCL): .NET का विशाल रेडीमेड क्लास संग्रह जो इनपुट/आउटपुट, स्ट्रिंग, डेटाबेस और नेटवर्किंग की मानक सुविधाएँ प्रदान करता है।

Namespace: संबंधित कक्षाओं (Classes) का तार्किक समूह (Logical Container) जो वैश्विक नाम टकराव (Naming Collision) को रोकता है (उदा. System.IO, System.Data)।

Event-Driven Programming: प्रोग्रामिंग प्रतिमान जहां प्रोग्राम का प्रवाह बाहरी घटनाओं (जैसे बटन क्लिक, माउस मूव, कीबोर्ड प्रेस) द्वारा निर्धारित होता है। .NET में इवेंट्स Delegates (टाइप-सेफ फंक्शन पॉइंटर्स) पर काम करते हैं।

UNIT 1 • TOPIC 7

Resource Cleanup: IDisposable Pattern बनाम Finalize (Destructor)

1. Technical Definitions & Concepts

Technical Definition: The IDisposable Pattern provides deterministic release of unmanaged resources (database connections, file descriptors, OS handles) via the Dispose() method or the Using block. Finalize (Destructor) provides non-deterministic cleanup executed asynchronously by the GC Finalizer thread.

सरल हिंदी में समझें: गार्बेज कलेक्टर केवल अपनी रैम साफ करना जानता है; वह खुले हुए डेटाबेस कनेक्शन या फाइल को बंद नहीं कर सकता। इसके लिए IDisposable इंटरफेस का उपयोग करके Dispose() मेथड तुरंत चलाया जाता है, या Using...End Using ब्लॉक लगाकर ऑटोमेटिक बंद कराया जाता है।

2. Comparison: Dispose() बनाम Finalize()

किस थ्रेड पर चलता हैएप्लिकेशन के मुख्य यूजर थ्रेड पर तुरंतबैकग्राउंड लो-प्रायोरिटी Finalizer थ्रेड पर

UNIT 1 • TOPIC 1 (CORE ARCHITECTURE)

Overview of .NET Framework, Features & Layered Architecture

1. Technical Definitions & Concepts

Technical Definition: The .NET Framework is a software development platform developed by Microsoft that provides a managed execution environment (CLR) and a comprehensive Base Class Library (BCL) for building secure, multilingual, robust applications.

सरल हिंदी में समझें: .NET Framework एक सुरक्षित और बहुभाषी सॉफ्टवेयर विकास मंच है। यह विंडोज़ ऑपरेटिंग सिस्टम और हमारी प्रोग्रामिंग भाषा (VB.NET, C#) के बीच एक सुरक्षा कवच (Layer) की तरह काम करता है, ताकि सिस्टम मेमोरी लीक और क्रैश से बचा रहे।

Memory ManagementAutomatic Garbage CollectionManual malloc/free (Memory Leak का जोखिम)

UNIT 1 • TOPIC 2

Managed Execution Process, MSIL & JIT Compilation Types

1. Technical Definitions & Concepts

Technical Definition: The Managed Execution Process compiles source code into CPU-independent Microsoft Intermediate Language (MSIL). During execution, the Just-In-Time (JIT) compiler translates MSIL on demand into native CPU machine instructions.

सरल हिंदी में समझें: VB.NET का कंपाइलर सीधे मशीन कोड (0 और 1) नहीं बनाता। वह पहले एक मध्यवर्ती कोड (MSIL) बनाता है। जब प्रोग्राम रन होता है, तो JIT कंपाइलर इसे तुरंत आपके प्रोसेसर के अनुसार मशीन कोड में बदलता है।

UNIT 1 • TOPIC 3 (CRUCIAL 10-MARK QUESTION)

CLR Internal Architecture & Generational Garbage Collection

1. Technical Definitions & Concepts

Technical Definition: The Common Language Runtime (CLR) manages code execution through subsystems like the Class Loader, Type Checker, JIT Compiler, and Garbage Collector. The Garbage Collector (GC) automatically tracks, marks, and frees unreferenced objects on the Managed Heap using an episodic Generational Model (Gen 0, 1, and 2).

सरल हिंदी में समझें: CLR .NET ka virtual machine engine hai. Iska sabse zaroori hissa Garbage Collector (GC) hai. Ye RAM mein jaakar un objects ko dhoondhta hai jinka kaam khatam ho chuka hai, aur unki memory ko apne aap free kar deta hai taaki program kabhi crash na ho.

2. Architecture Flowchart (Generations 0, 1, 2)

3. Comparison Table: Garbage Collection Generations

GenerationObject LifespanGC Collection FrequencyPerformance Impact
Gen 0बहुत छोटा (लूप वेरिएबल्स, अस्थायी डेटा)अत्यधिक तीव्र एवं बार-बारनगण्य (लगभग शून्य प्रभाव)
Gen 1मध्यम (शॉर्ट से लॉन्ग टर्म संक्रमण)मध्यम आवृत्तिबहुत कम प्रभाव
Gen 2दीर्घकालिक (स्थिर डेटा, पूरे ऐप के जीवनकाल तक)बहुत कम (Full GC)अधिकतम (UI कुछ मिलीसेकंड्स रुक सकता है)

UNIT 1 • TOPIC 4

CTS, CLS, Value/Reference Types, Boxing & Unboxing

1. Technical Definitions & Concepts

CTS (Common Type System): .NET ka rulebook jo tay karta hai ki har language mein data types kaise declare aur store honge taaki type safety bani rahe.

CLS (Common Language Specification): Rules ka wo common set jiska paalan karne par alag-alag languages (jaise VB.NET aur C#) bina kisi problem ke aapas mein communicate kar sakti hain.

Boxing & Unboxing: Value Type (Stack) ko Reference Type (Heap) mein badalna Boxing kehlata hai. Object se wapas Value Type nikalna Unboxing kehlata hai.

UNIT 1 • TOPIC 5

Assemblies, Metadata, Manifest एवं GAC (Global Assembly Cache)

1. Technical Definitions & Concepts

Assembly: .NET application ka deployment unit hota hai (.dll ya .exe) jo puri tarah se Self-Describing hota hai.

Manifest & Metadata: Manifest assembly ki ID card hai (name, version, dependencies). Metadata binary data hota hai jo har class, method aur variable ki details store karta hai.

Global Assembly Cache (GAC): Machine-level central folder (C:\Windows\Assembly) jahan shared assemblies ko Strong Name ke saath install kiya jata hai taaki sabhi applications unhe use kar sakein.

Base Class Library (BCL/FCL), Namespaces एवं Event-Driven Programming

1. Technical Definitions & Concepts

Base Class Library (BCL): .NET ka built-in class collection jo standard tasks (I/O, database, collections) ke liye ready-made code deta hai.

Namespace: Related classes ka logical container jo naming conflict ko rokta hai (jaise System.IO, System.Data).

Event-Driven Programming: Wo system jahan code user actions (button click, typing) par chalta hai. VB.NET mein events ko handle karne ke liye Delegates ka use hota hai.

UNIT 1 • TOPIC 7

Resource Cleanup: IDisposable Pattern बनाम Finalize (Destructor)

1. Technical Definitions & Concepts

Technical Definition: The IDisposable Pattern provides deterministic release of unmanaged resources (database connections, file descriptors, OS handles) via 618

Technical Definition: The IDi sposable Pattern provides deterministic release of unmanaged resources (database connections, file descriptors, OS handles) via the Dispose() method or the Using block. Finalize (Destructor) provides non-deterministic cleanup executed asynchronously by the GC Finalizer thread.

सरल हिंदी में समझें: Garbage Collector केवल अपनी मेमोरी साफ करता है; खुले हुए डेटाबेस कनेक्शन या फाइल हैंडल्स को यह तुरंत बंद नहीं कर सकता। इसके लिए IDisposable इंटरफेस का उपयोग करके Dispose() मेथड तुरंत चलाया जाता है, या Using...End Using ब्लॉक लगाकर ऑटोमेटिक सुरक्षित तरीके से बंद कराया जाता है।

2. Comparison: Dispose() बनाम Finalize()

तुलना बिंदुDispose() [IDisposable]Finalize() [Protected Overrides]
कॉल करने का समयDeterministic (डेवलपर तय करता है कि तुरंत कब बंद करना है)Non-Deterministic (GC तय करता है कब चलाना है)
किस थ्रेड पर चलता हैएप्लिकेशन के मुख्य यूजर थ्रेड पर तुरंतबैकग्राउंड लो-प्रायोरिटी Finalizer थ्रेड पर
प्रदर्शन पर प्रभावसर्वोत्तम (संसाधन तुरंत मुक्त हो जाते हैं)धीमा (ऑब्जेक्ट को कम से कम दो GC साइकिल तक जीवित रहना पड़ता है)
सुरक्षित सिंटैक्सUsing conn As New SqlConnection() ... End UsingProtected Overrides Sub Finalize()
